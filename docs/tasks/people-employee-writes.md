## 2. New classes (`WorkforceOne\People`)

**Ports** (held by `PeoplePorts`; built only in `trait-services.php` and the unit fakes): `ShiftHistory` (`fromBeginning(e,shift)`, `from(e,shift,date)`, both `true|string`; the adapter holds the Schedule constant), `AppSessions` (`revoke(wpUserId, reason)`), `OpenAdvances` (`enabled()`, `leftFor(e)`; two methods so the old short-circuit order is kept), `WpUsers` (`exists(id)`), `OrgFeature` (`enabled()`, `titleRequired()`, called lazily at the old points). Reused: `EmployeeChanged`, `OrgClock`, `AuditLog`.

**Stores** (SQL verbatim, raw wpdb values): `PeopleStore` gains `former`, `status`, `domainOwner`, `userOwner`, `insert`, `insertId`, `updateFields`, `archive`, `setPicture`, `adminCount`, `adminPage` (the two-step prepare with `esc_like` kept), `pickList`, `activeTitles`, `contactList`, `directory`, `publicProfile`, `lastError`. `DepartmentStore` gains `activeIdUnlimited` (no `LIMIT`, unlike `activeId`). `TeamStore` gains `countActiveInDepartment`, `managesElsewhere`, `pageTeams`, `teamsOfWithManager`, `activeNameRows`, `activeNames`, `namesByIds`, `activeList`. Existing methods are reused where the text is identical.

**Services** (no SQL, no WordPress calls): `EmployeeService` (`check` builds the facts in the old order: department_ok, domain_taken, user_ok (only when user > 0), user_taken, title_missing (new + empty title), supervisor reads (`activeId`, `relatedEmployee`, and for an existing employee `OrgTree::wouldLoop` fresh each time), the teams count when teams were posted, `manages_team_elsewhere` only on a department change; then `EmployeeRules::check`), `create`, `former`, `status`, `update`, `archive` (returning `{error, notice, advance_left}`), the page reads; `ProfileService` (`avatar`, `reset`, `photo`; the employee id always comes from `current_employee()` in the controller). `Services` gets lazy `employees()` and `profiles()`.

**Controllers keep:** `can('ews_manage_employees')` + `wp_die('Access denied')`, nonces, `is_user_logged_in`, `current_employee()`, `$_POST`/`$_GET`/`$_FILES` parsing, `ensure_*_schema`, `employee_last_working_day_input` (feeds payroll; computed after the find and the check, as now), `employee_admin_redirect` with the same arguments, `get_users`, `shifts()`, `render_template`, `advance_money`, the upload pipeline, `delete_employee_profile_image_file` at the old points, and the profile's three audits. Return points: update returns at `save` (shift refusal, failed UPDATE, failed `supervisorChange`/`setSupervisorOnly`) and `teams` (after the sync); create at `save` (failed insert or `setSupervisorOnly`).

## 3. Order of reads and writes, transactions, lock order

`employee_update`: `former` → schema checks → facts → `$lastDay` (no SQL) → only if the shift changed: `ShiftHistory::from(today)` (inside: `GET_LOCK(shift_periods_<id>)` → START → periods SELECT/INSERT/UPDATE → SELECT → `UPDATE employees SET default_shift_id` → COMMIT → `RELEASE_LOCK` → `shift_period_set` audit; anything but `true` returns `save`) → `updateFields` without `default_shift_id` (3.31.119; `job_title` left out when not posted, NULL when `''`) → `changed($id, wpUser)` → revoke the old user's sessions when `!empty(old wp_user)` and (old active and new inactive, or the user changed), reason `employee_archived` if the new state is inactive else `employee_unlinked` → `managerOf` → chart on and supervisor changed: `supervisorChange` (source `employees`, today, status `done`) then the `org_move` audit with the `requests` suffix; otherwise `setSupervisorOnly` → `syncEmployee` → `employee_update` audit, then `employee_status_change` when the status changed → advances short-circuit.

`employee_save`: check → insert → `insertId` → `changed` → `ShiftHistory::fromBeginning` (result ignored) → `setSupervisorOnly` → audit. `employee_archive`: status → `$lastDay` → archive → `changed($id,0)` → revoke when a user is set → audit when old ≠ 0 → advances.

**Transactions:** `EmployeeService` never calls `Transaction::begin`. MySQL's `START TRANSACTION` silently commits an open transaction, so wrapping the update would break the shift history and org-move atomicity. **Lock order everywhere:** named lock `shift_periods_<id>` → employees row. `employee_update` takes the row lock only in its autocommit UPDATE, after the named lock is released; the org transaction (relationships → approval_steps → org_moves) opens only after that UPDATE committed. Rules: never hold the employees row while calling the `ShiftHistory` port; never call the port inside the org transaction.

## 4. Golden harness
`tests/golden/actions_employees.php` (keys `employees:*`), recorder and fault filter of `actions_org.php`, plus a fault variant that rewrites a match to `SELECT 0` (so `GET_LOCK` gives `busy`). Seed additions (plain SQL): a free WordPress user, a device session for an employee's user, an advance being paid, an employee without shift history. Scenarios: **save** (denied, bad nonce, each error code, ok with supervisor and title, app referer, faults on INSERT employees / relationships / periods); **update** (not_found, self_supervisor, loops, manages_team, team_department, no change, shift change / busy / fault on periods INSERT / fault on the UPDATE after the shift, deactivate with valid / invalid / no date, sessions revoked, relink, reactivate, supervisor change with the chart off and on incl. a moved request and notification, fault on `approval_steps`, fault on team_members INSERT, department change with teams, open advance, title absent / `''`); **archive** (denied, bad nonce, not found, date, invalid date, already archived, sessions, advance, fault); **profile** (not logged in, bad nonce, no employee, avatar ok / invalid / fault, reset, upload errors `upload` / `size` / `type`; a successful upload cannot run in process and stays in `e2e_my_profile.py`). Pages: employees with `employee_error=teams`, with `employee_notice=archived&advance_left=…`, with the chart on; employee profile with teams; my profile with an avatar; app employees; people with search + team; colleague profile. `run.py` sanity check so the trace cannot prove nothing; self-test: one extra query in `employee_update` must fail the trace.

## 7. Risks
Money: `last_working_day` feeds payroll; it stays in the controller and is written only at the old points (`e2e_money_safety`, `e2e_advances`, payroll). Permissions stay in controllers; the profile id comes only from `current_employee()`. Concurrency: §3; `domain_taken` / `user_taken` are check-then-act (the unique `domain_name` key turns a race into a `save` error; `wp_user_id` is not unique, kept); no check that the row is unchanged since it was read (kept). Sessions: the revoke stays after the UPDATE and the invalidation and before the org change (`e2e_api_auth`). Multisite: the employees table is fixed; teams and departments follow the container prefix (`*_mu`). `e2e_org_moves.py:190-222` posts `ews31_employee_update` and must stay green. No upgrade path.

## 8. Quirks preserved (numbering continues after s)
t. `employee_save` ignores `shift_period_add`'s result, so it says "added" even without history. u. `employee_archive` on an already-archived employee rewrites `last_working_day` (money) and revokes again, with no audit; it also clears the runtime cache without the WordPress user. v. `employee_save` checks the posted `team_ids` but never saves them. w. After the employee UPDATE, a supervisor or teams failure redirects before the `employee_update` / `employee_status_change` audits; sessions may already be revoked. x. A form without `active` reactivates the employee (default 1). y. `profile_photo_save` does not clear the runtime caches after its write (harmless: it redirects at once).

## 9. Decisions, commit order, test plan
Decided (technical): port names as in §2; the `Employees` namespace joins the slice; three-step service calls (find, check, write) so `$_POST`-derived values stay in the controller; separate store methods where the SQL differs by a `LIMIT` or a return type; profile audits stay in the controller.

Commit order (green at each step): 1 harness on unchanged code (`actions_employees.php`, seed, pages, `run.py` check; base == head; self-test); 2 namespace list in `modules.json`; 3 ports, `PeoplePorts`, adapters (unused); 4 Stores, fakes, storage contract; 5 `EmployeeService::check` + the `employee_admin_input` delegator; 6 `create`; 7 `archive`; 8 `update` (own commit: lock, sessions, org); 9 page reads; 10 `ProfileService`; 11 `modules.json`, baselines, docs, CHANGELOG, version, `expected.json`.

Tests: unit, phpstan, phpcs, `check_modules`, `check_layers`, translations, golden (`employees:*` new; `org:*`, `people`, `approvals` unchanged); e2e: employees, employee_profile, my_profile, people, org_moves, org_chart (+ browser), organization, shift_history, api_auth, money_safety, advances, payroll, speed, query_batching, people_store, schema, and every `*_mu`.
