# L4 People move (Controllers → Services → Stores): design

**Status:** design by the read-only architect on 3.31.132 (`3b323ba`), saved before implementation (CLAUDE.md). Move only: same behaviour, same SQL text and order, same transactions, notifications, audit rows, hooks, options and schema. No new option or switch, so "off changes nothing" holds trivially. `tests/golden/expected.json` stays empty (only `release` changes). Model: the Schedule days move (3.31.127) and the approvals engine move (3.31.128, `docs/tasks/approvals-engine-move.md`). Open questions for the owner are in §9; their answers are recorded at the end of that section.

## 1. Scope and slicing

| Release | What moves | Size |
|---|---|---|
| **L4a People reads (first)** | The people read API, the shared "names by ids" read, the shift primes and memos, `emps()`, the reporting-line / department / team reads. Schedule's two shift reads join the same Store. Enrols all six tables in the layer baseline. | M |
| **L4b Org writes** | Reporting-line writes, org moves (transaction, claims, cron, recovery), org import apply, departments and teams CRUD, `sync_employee_teams`, the admin pages' reads for departments, teams and the chart | L (concurrency) |
| **L4c Employee writes and pages** | `employee_save` / `employee_update` / `employee_archive`, `admin_employees`, profile picture writes, the people-table reads of the people pages | M–L (money-adjacent, sessions) |
| L4d (optional, not a move) | Turn other modules' "name next to a row" JOINs into `namesByIds`; changes SQL, needs `expected.json` entries | S each |

Org comes before employee writes because `employee_update` calls the org-move and team code; moving employee writes first would need a temporary port back into the trait (open question 1).

**Explicitly NOT moved in any L4 release:** schema (`ensure_departments_schema`, `ensure_teams_schema`, `ensure_org_moves_schema`, `ensure_employee_email_column`, the relationships CREATE in `ensure_approval_schema`, the employee ALTERs); other modules' JOINs with employees, departments and teams (read-model debt that stays in the baseline; payroll moves last); `current_employee()` and its cache (request actor, `trait-api-auth.php:211` writes into it); permission and scope logic (`current_department_id`, `department_scope_allows_employee`, `department_scoped_employees`, `department_employee_ids`, `org_app_allowed` and its memo, every `can()`); presenters (`employee_picture_url`, `people_picture`, avatar catalog, `org_chart_data`, `team_content`, notices); settings readers; uploads and the org export/import preview files; other modules' tables read by people pages.

## 2. New classes (`WorkforceOne\People`, `workforce-one/src/People/`)

### 2.1 L4a
- **`PeopleMemo`**: a plain holder for one PHP request replacing the two statics (`$shift` by employee, `$active` list; `forgetShift(id)`, `forget(id)` = the people part of `invalidate_employee_runtime_cache`). It is held in a **static** in `trait-core.php` so it is shared by every plugin object and every prefix, as the replaced statics were.
- **Stores** (interface in `src/People/Data/` + `WordPress*Store`; SQL copied verbatim: same text, whitespace, `LIMIT`, chunks of 500; raw wpdb return types; the same casts at the same points): `PeopleStore` (employees: `byId`, `activeByUser`, `activeNamesByUsers`, `rowsByIds`, `briefsByIds`, `activeId`, `name`, `userId`, `activeIdsInDepartment`, `activeInDepartment`, `activeBrief`, `shiftIdOf`, `shiftIdsOf`, `setShiftId`, `allShiftIds`, `activeList`, `activeUsers`, `activeIds`, `activeUserIds`, `activeCount`, `activeAll`, `attendanceEnabledValue`, `shiftIdNow`, `orgRows`), `ReportingStore` (`tableExists`, `relatedActive`, `supervisorIdsOf`, `currentManagerId`, `activeSupervisorRows`, `hasActiveReport`), `DepartmentStore` (`tableExists`, `activeManagerOf`), `TeamStore` (`activeManagerFor`, `activeMemberIds`, `activeTeamIdsOf`, `activeTeamRowsByEmployees`). The `employees` table name comes from the constructor argument (the plugin's `$this->employees`); the others from `$db->prefix`.
- **Services:** `PeopleDirectory implements \WorkforceOne\Platform\People` (employee lookups, the shared `namesByIds` built on `briefsByIds`, shift id reads with the `property_exists($p,'default_shift_id')` rule, `setShiftId` forgets the memo **before** the UPDATE, active lists, `activeAll` / `activeAllLoaded` (a null read is not remembered), `attendanceEnabled`, `forget`) and `OrgDirectory` (`relatedEmployee`, `supervisorIds` (zero-filled, newest row wins), `managerOf`, `managerIds` (exact order: active ids → return `[]` if none → `tableExists` → zeros if missing → rows), `hasReports`, `orgRows`, `departmentManager`, team reads).
- **Container** (`src/Platform/Services.php`): holder `PeoplePorts` (L4a: only the memo), `$tables['employees']`, lazy `peopleStore()`, `reportingStore()`, `departmentStore()`, `teamStore()`, `people()`, `org()`; the old `People` argument and the anonymous adapter in `includes/trait-services.php` go away (Schedule gets `people()`; same SQL).

### 2.2 L4b (org)
Writes added to the Stores (`ReportingStore`, new `OrgMoveStore`, `DepartmentStore`, `TeamStore`) and services `OrgMoveService` (check, apply, supervisorChange in a `Transaction`, setSupervisorOnly, schedule, applyDue, recover, cancel, forChart), `ReportingService`, `DepartmentService`, `TeamService` (incl. `syncEmployeeTeams`), `OrgImportService`. Ports in `PeoplePorts`: `OrgNotifier::requestsMoved`, `EmployeeChanged::changed`. `check_layers`: slice `namespace` becomes a list so services may use `MoveRules` / `OrgTree` / `ImportPlan` / `OrgRules`. Lock order (to document in `OrgMoveService`): relationships rows → `approval_steps` (engine with `$manage=false`) → `org_moves` → COMMIT → notify. Claims stay verbatim; cron runs with actor 0.

### 2.3 L4c (employees)
`PeopleStore` write methods, `TeamStore` reads for pages, `EmployeeService` (facts for `EmployeeRules::check`, create, update, archive returning codes at exactly the old redirect points) and `ProfileService`; ports `ShiftHistory::add`, `AppSessions::revoke`, `Advances`, plus `OrgMoveService`, `TeamService`, `EmployeeChanged`.

## 3. Delegators (same names and signatures)

## 4. Request caches and speed
`$ews_people_shift_memo` → `PeopleMemo::$shift` (cleared by `setShiftId` before its UPDATE and by `invalidate_employee_runtime_cache($id)`); `$ews_emps_cache` → `PeopleMemo::$active` (cleared by any invalidation). `current_employee` cache, `org_app_allowed_memo`, schedule and location statics are unchanged. No new cache, no merged reads, the repeated `SHOW TABLES` stay. Primes keep one query per 500. Guards: `e2e_speed.py` (8 vs 78 people, `large <= small+2`), `e2e_query_batching`, the golden "no more queries per page" rule and the `actions_people` trace counts.

## 8. Risks and edge cases
**L4a:** wpdb returns strings and nulls, so Store returns stay raw and the golden JSON compares types; the approvals trace contains people SQL through `ApprovalDirectory`, so any text drift fails it; the memo must stay process-wide; multisite (employees fixed table, the rest by prefix; the `*_mu` suites stay green); statement order (`people_manager_ids`: active ids, early return, `SHOW TABLES`; `ensure_*_schema` before team and department reads; `prime_shift_cache` after the `emps()` read; `people_set_shift_id` runs inside the shift-history transaction, forget then UPDATE); permissions (department scoping stays in the trait on the same data; `employee_profile_content` keeps `AND active=1`; `people_content` keeps `active=1` and `LIMIT 500`). No money, no concurrency beyond the shift write.
**L4b:** lock order above; conditional claims verbatim (`org_moves_maybe_due` can run twice at once); cron with actor 0; `team_save` keeps START / COMMIT with ROLLBACK sent from `team_redirect_error`; approval routing through department and team resolvers (covered by the approvals trace and the new org trace); `e2e_org_moves` fault injection stays green.
**L4c:** `last_working_day` (payroll pays up to it) stays in the controller; `advance_left_for` read only; revoking sessions stays after the UPDATE and the invalidate, before the org change; the shift period add stays before the UPDATE (3.31.119); `domain_taken` / `user_taken` are not atomic (kept); file deletion after a failed DB write stays in the controller.
**No schema change, no upgrade path.**

**Quirks a faithful move preserves** (separate releases, each the owner's call): (a) `people_set_shift_id` does not clear the `emps()` list, so `default_shift_id` in the list is stale for the rest of that request; (b) inside `switch_to_blog()` people reads hit the main site's employees while departments, teams and relationships use the switched prefix; (c) `approval_relationship_save` deactivates twice, runs no transaction, skips the org-move history when the chart is on and always reports "saved"; (d) `employee_save` inserts the row and saves the supervisor separately, so a supervisor failure reports `save` but the employee exists; (e) `team_delete` ignores the members update result; (f) the org chart calls `people_name` once per archived manager and per moved name (a bounded N+1).

## 9. Open questions for the owner, and the recommended first release
1. Order of the releases: L4a reads → L4b org → L4c employee writes (recommended), or writes before org with a temporary port.
2. Namespace: new code in `WorkforceOne\People` with a namespace list (recommended).
3. Baseline: enrol all six tables in L4a with one `--allow-increase` (recommended), or per release.
4. Other modules' same-SQL reads in L4a (office-minimum, frontend ×2, signin-evidence, api-auth gate, time-report scope, achievements-admin, reports): move now (−1 crossing each) or leave as debt. Payroll :122 is excluded either way.
5. Names-by-ids conversions (table-crossing step 1): not a move (changes SQL, one more query per page); its own release later.
6. Memo scope: process-wide, shared across sites (faithful, recommended) or per site (visible change).
7. `current_employee()` and its cache stay in `trait-core` (recommended).
8. Dead functions: delete (recommended).
9. The relationship functions: move the `approval_*` definitions to a people trait with names kept (recommended).
10. Quirks a–f: keep in the move and fix each separately (recommended, as 3.31.128 did).
11. The harness may run admin-post handlers in process (`GoldenExit`) from L4b on (about +1–2 minutes of CI).
